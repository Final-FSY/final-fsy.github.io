手机遥控电视

电视遥控器总找不着？用手机浏览器遥控：树莓派做网页服务，adb 遥控安卓电视盒子。

起因

电视遥控器经常随手乱放，而且三星电视自带的遥控器按键有限。家里正好有常开的树莓派和一台 Orange Pi Zero 3（刷了安卓 12 TV 固件当电视盒子用，HDMI 接到三星电视上），想做一个"手机打开网页就能遥控盒子"的方案。

方案与实现

链路：手机浏览器 → HTTP → 树莓派 server.py（192.168.31.187:8088）→ 常驻 adb shell 管道 → 盒子（192.168.31.69，Orange Pi Zero 3 / Android 12 TV）端 FIFO → C 注入器直写 /dev/input/event1。

按键注入：盒子是安卓系统，树莓派通过 adb 通道把按键码送到盒子上的注入器（injector.c，监听 FIFO），注入器按 Linux input 协议（EV_KEY + EV_SYN）直写输入设备节点，等效于物理按键，单键延迟约 1ms。

特殊键：电源键（KEYCODE 26）注入器不认，改走 framework 的 input keyevent 命令。网页端支持长按连发。

开机自启：树莓派侧 systemd 服务 tv-remote 开机自启；盒子重启后 server 会自动重拉注入器，断线自愈。

顺带研究过 HDMI-CEC：盒子其实能通过 CEC 单向控制电视电源（One Touch Play），但这条路有副作用（见坑），所以最终方案不依赖 CEC，纯 adb + 注入器。

踩过的坑

· 注入目标不是电视而是盒子：三星电视没有安卓系统、没有 adb，能遥控的是接在它 HDMI 口上的安卓盒子；

· sunxi-ir-uinput 设备吃的是 Android keycode 而不是 Linux keycode，直接写会错键；

· CEC 引发电视自开关机：乐播/AirScreen 投屏 App 启动时通过 CEC 发 One Touch Play 唤醒电视，反复折腾后禁用 hdmi_control_tv_wake_on_one_touch_play 和 send_standby_on_sleep 才消停；

· 盒子固件会把 CEC 开关设置重置回开（vendor 层行为），硬改 settings 无效，只能避开；

· 曾尝试改 /vendor 下的 init rc 停掉 CEC HAL，写入失败把 .rc 文件搞成 0 字节，盒子重启卡 Logo，重刷固件才救回来（教训：别乱动 /vendor）；

· adb 管道要常驻，否则每次按键都重新建立连接，延迟明显。

现状

手机浏览器访问 8088 端口即可遥控，日常够用。CEC 部分属于研究性质，结论是"电视遥控器反向控制盒子这条路走不通，盒子控制电视电源又容易误触发，最终老老实实用 adb"。
